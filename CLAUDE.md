# StreamAssist — context for Claude

An "everything app" for streamers (Windows, .NET 10, Avalonia 12, CommunityToolkit.Mvvm): keybinds, a Twitch chatbot, alerts / redeems, Voicemeeter, OBS, Spotify and SQLite tables, all driven by Scratch-like blocks. It glues existing tools together rather than replacing them. This file holds the rules and the non-obvious parts; details (block lists, settings, field names) are in the code, search there.

## Working with me

- This is my first desktop/frontend app: explain the reasoning behind UI/MVVM/Avalonia suggestions, not just code.
- Don't fix unrelated bugs unless asked, point them out (see Known issues).
- Don't make changes just for the sake of changes. Commit only when asked.
- Never read or print `Config/auth.json` or any secret/token.
- The user's app may be running: check `tasklist | grep -i streamassist` before building into `bin/` or touching `Config/`. While it runs, build/test into another folder (`dotnet build -o <tmp>`, `dotnet test StreamAssist.Tests -o <tmp>`) and never edit `Config/` (the app would save over it). Back up a config file before editing it.
- No auto-migration code for old save formats: a format change gets a one-off conversion of my `Config/` files (app closed, backed up), then a load check with the real models.
- Don't simulate clicks or typing in the app (they can land in another window).
- **Key input must keep working while the app isn't focused:** raw input is registered with `RIDEV_INPUTSINK` on the main window. Never change that or route keys through anything that needs focus.
- **Console = failures only** ("no news is good news", `AppLog`, `[time] kind - message`): `WriteError` (failed), `WriteWarning` (went wrong but the app carried on, e.g. a dropped connection), `WritePrompt` (the user must act, e.g. a login link); `WriteLine` only for the App Console Message block. Short (5-10 words), no full stop, outside details in brackets at the end: `can't send chat message, twitch not connected`, `streamer disconnected from twitch (reason)`. A block's error starts with its name. Asking for what's already the case is silent success, except something the user named that isn't there (`!delcom !lurkk` → not found). Ask before adding any other kind of message.
- Twitch blocks act only on my own channel (no raids, whispers, other channels). The bot account only has chat + moderation scopes; everything else is done as the streamer.
- Built-in chat commands confirm briefly in chat when they work (`Command !lurk added`).

## Layout

- `Shell/`: main window, panels, `GlobalContext` (static service locator), `MainWindowViewModel` (composition root: loads models, creates managers), `WindowLayoutModel` (`Config/window.json`: window, selected tab, splitter sizes by name via `GetPanelSize`/`SetPanelSize`, collapsed block groups).
- `Components/<Name>/` one folder per feature, each split into **Model/** (data only, JSON, raises events, never does work), **Background/** (managers created once at startup that listen to models and do the work), **UI/** (view models made when a tab opens, disposed when it closes; they change things only through model methods, never managers). Flow: UI → model method → model event → background + UI. Feature blocks live in their component's `Actions/`, `Conditions/`, `Values/`; `Components/Blocks/` holds the block system and the generic logic blocks.
- `Core/`: knows nothing about features (if it references a component it doesn't belong here). `Persistence/`: `JsonFileStore`, `CredentialStore` (every secret in one git-ignored `Config/auth.json`, a section per service), `AppPaths`. `Utilities/`: `GrowingList<T>` (a list that always ends in one empty item), `Formula`. `Mvvm/`: base classes, `CommitOnLeave`, `Flash`.
- `Styles/Resources/` (`Brushes`, `Typography`, `Spacing`) and `Styles/Controls/` (one file per control type, app-wide style classes). `App.axaml` lists them in order.
- **`AppPaths`**: the app folder is the exe's folder, or the project folder when run from `bin/` (found by `StreamAssist.csproj`). `Config/` and `Assets/` live there; both are git-ignored. Paths in blocks (sounds, …) are relative to `Assets/` (`Sounds/boom.mp3`, folders Sounds / Images / Videos made at startup) and can never leave it (`TryResolveAsset`); the file picker only takes files inside it. App files that must ship (e.g. a future logo) don't go in `Assets/`.
- `StreamAssist.Tests/`: see Tests.

## Rules

- **Everything the UI can do is a public model method** with the rules enforced in the model, so blocks, chat commands and code can do anything the user can and the UI follows the model's events.
- Public `TryXxx(...)` validates, logs via `AppLog.WriteError`, returns bool, and calls a private `Xxx(...)` that does the work and raises the event.
- Event subscriptions go through paired `SubscribeToXxx` / `UnsubscribeFromXxx`; `Dispose()` unsubscribes everything. Keep a reference to what you subscribed to (don't re-read a property that may have changed, e.g. a config switch).
- JSON: public getters `[JsonIgnore]`, saved through private `[JsonInclude] [JsonPropertyName("camelCase")]` properties. Cross-links resolve in `IJsonOnDeserialized.OnDeserialized` / `AttachXxx`.
- Style: `_camelCase` fields initialised in the constructor, `// section` headers, three blank lines between members, comments explain why.
- `CallbackBlocker` stops UI → model → UI loops. `AttachUnbindSelf(...)` lets a child remove itself from its parent (an emptied bindable unbinds itself).
- Threading: everything runs on the UI thread (raw input arrives via `KeyboardInputManager.WndProc`). Integrations calling back on other threads switch with `Dispatcher.UIThread.Post` before touching models.

## XAML / look

- `ViewLocator` maps `FooViewModel` → `FooView` (same namespace): no DataTemplate that only wraps the matching view.
- Colours in `Brushes.axaml`, spacing in `Spacing.axaml` + `Styles/Gap.cs`, never hard-coded in views. Views use `{StaticResource}`, style files `{DynamicResource}`. View-only styles go in the view's `<UserControl.Styles>`. Class names are case-sensitive.
- **What the user made is outlined green** (`Bound`: blocks, bound keys, docks; red when off, docks can't be); what's permanent is divider lines and plain text.
- Outlines only, calm low-contrast palette (old palette/fills kept in a comment in `Brushes.axaml`). The palette colours are named by meaning (`ColorBackground`, `ColorLine`, `ColorGhost`, `ColorSelected`, `ColorEnabled`, `ColorDisabled`, ...); views use the brushes. Panel fills are black at alpha 1 (`#01000000`), not Transparent: a fully transparent fill isn't hit-testable, so clicks/drops would only land on text.
- **Everything clickable has a border.** **Ghost fields** (`Ghost` brush, one colour for border and text, full strength): the "new thing" boxes (`TextBox.New` while empty: the empty row of a growing list, New table/config, …) and empty block slots (`DropZone`). `TextBox.Plain` (no border) only for text that can't be edited.
- `Border` has no global style: `Classes="Panel"` for the rounded look, `Divider` for lines. Buttons: `Small` / `Medium` / `Large`, plus `Square` for icons; plus/minus are full-width `＋` / `－`. Collapsible list headings: title text + a `Square Small` arrow button (only the arrow toggles).
- A box that must show a value the view model resets (cleared "new" boxes, refused values) commits on leave (`CommitOnLeave`, `Commit` class) instead of binding Text directly: a TextBox ignores changes to the property it's writing. Enter applies it, except in a multi-line box (`AcceptsReturn`), which keeps Enter for new lines.
- **No typed spacing numbers in views.** `Spacing.axaml` holds only the **base values** (line thicknesses, `LineGap`, `ContentGap`, the six content gaps, `CornerGap`, `BoxTextInset`) plus sizes; spacings use them as `{DynamicResource SmallVerticalGap}`. Every other margin/padding is a **recipe** in `Styles/Gap.cs` (`SpacingRecipes.Recipes`, e.g. `"P,P-3,P,P"`, letters = base values, `P` = ContentGap - LineGap) used as `Margin="{s:Gap ScrollInset}"` (`xmlns:s="using:StreamAssist.Styles"`), recomputed whenever the app's resources change, so a base value edited in the Themes tab moves everything live. Only font trims (`0,-5,0,0`, the Subheading style) and the insert line's math stay typed. A new margin gets a recipe (reuse one if it's the same shape), with a comment saying what it's for; a new base value goes in `Spacing.axaml` and `SpacingRecipes.BaseValues`.
- **Spacing (keep exact, it's very visible), lines and regions:** `ThinLineThickness` (1, dividers) and `ThickLineThickness` (5, splitters) alone set line widths. Every line keeps `LineGap` (5) clear on each side through its own style (`Border.Divider` / `Border.VerticalDivider` / `GridSplitter.ColumnSplitter` / `RowSplitter`; splitters sit in `Auto` columns/rows, hidden with their panel via `PanelViewModel.IsShown`); the window edge and Gapped scrollbars count as lines. Nothing goes in a line's zone, not content and not other lines (a divider spans its region, so it stops `LineGap` short of a splitter). Content sits `ContentGap` (10) from every line: regions pad by `ContentPadding` (= ContentGap - LineGap, 5) inside the zones (`PadSides`, `PadAll`, `ScrollInset`, `ScrollEdgeMargin`, `PadLeft` / `PadRight`; a stack of sections and dividers is spaced `ContentPadding`). **Content to content** is `Small` / `Medium` / `Large` + `Horizontal` / `VerticalGap` (5 / 10 / 15), set on the container (StackPanel `Spacing`, Grid `ColumnSpacing` / `RowSpacing`) by the direction it stacks in, not as margins on the elements or spacer elements; a one-off different gap is a split stack or a named margin. Everything starts at Small, except stacks around big titles. **Boxes (blocks, docks):** their border is a line, so they keep a `LineGap` ring inside it (`LineZoneAll`); lines and nested blocks sit at the ring, content pads itself `ContentPadding` more (title, setting rows, slot labels, empty slots and value boxes via `PadAll`, scoped to `BlockView`'s styles), so a placed block fills its slot and its border lands at the ring. Corner buttons pull back out of the ring (`RingCornerMargin`) to stay `CornerGap` from the border. A dock's header is `PadAll` like a panel's. `ControlHeight` (25) for every single-line control. Content-to-content gaps are still being revised.
  - A panel's ScrollViewer gets `Classes="Gapped"` and no margin; its content gets `ScrollInset`. Not on scroll viewers inside controls. Bars stay thin.
  - Main scroll areas end with `<Border Padding="{StaticResource ScrollEndPadding}">`.
  - Headers: `PadAll` + `Height="{StaticResource ControlHeight}"` (`MinHeight="0"` on boxes), a `Divider` under it (its style brings its margin).
  - **Big titles** (`TextBlock.Title`, 18px: App, Twitch, Built-in, Voicemeeter, ...) are `LargeVerticalGap` (15) from what's around them (a section is a stack spaced Large: the title, then a stack of its content), with the font's own space taken back by `BigTitleMargin` (LV - C - 5 above, -4 below), so the letters are ~15 from the line above and from what follows. **Subheadings** (`TextBlock.Label.Subheading`, e.g. Alerts / Redeems) are `MediumVerticalGap` (10) from what's around them, the class pulls back the font's space. Pages of sections and dividers (Events, Connections) use `ScrollViewer.Gapped.Lined` (no side padding, so the dividers reach `LineGap` from the edges; sections pad themselves with `PadSides`). Measure pixels after changing any of these.
  - Status text that isn't clickable has no border (e.g. a connection's status is coloured text).

## Blocks

- Every trigger (key, chat row, redeem, alert) owns a `BindableModel` whose root is a `BlockSlotList` (like a List block without its box, saved as `"root": [...]`; so a script can be rearranged in place, a block waiting at the bottom meanwhile); blocks nest Scratch-style. The binding unbinds itself when the last root block goes. `TriggerStart/Stop/Once` run the root blocks in turn (an error or Stop ends the run, `SafeRunAsync` returns false) with a `TriggerContext` (phase, cancellation token, parameters). Execution is async; pass `context.CancellationToken` to waits; disposing a bindable cancels its runs.
- Errors are logged where they happen: `throw Fail("reason")` logs `error - <block>: <reason>` (value slots add their label) and throws `BlockFailedException`, which stops the run; `SafeRunAsync` at the root only logs unexpected exceptions. **Stop** throws `StopRunException`, ended quietly. A disabled block skips itself and everything inside.
- Kinds: `ContainerBlock` (slots), `ActionBlock`, value blocks `ValueBlock<T>` (text, int, double, bool, char); `ConditionBlock` is the bool one (disabled/empty = false). `AdaptableValueBlock` ("any type": Convert, Expression, Get Table Value, getters) switches to the kind of the slot it's dropped in; changing its dropdown to a kind its slot can't take is refused.
- **Values:** a setting that can come from logic is a `ValueSlot<T>`: typed text (`{name}` parameters and `{var.name}` variables filled in, then read as the slot's kind) or a value block placed in it (wins over the text; disabled falls back to it). `ValueTypes` decides all conversions. `AnyValueSlot` takes any kind (Equals). Growing slot lists: `ValueSlotList` (one kind), `ValueSlotPairList` (name + value rows: String Builder, Set Parameters, Set Table Row).
- **Expression** (`Core/Utilities/Formula`, the DynamicExpresso library): a typed C# expression (maths, `&& || !`, `? :`, `"text"` and its methods, `Math.*`, plus short `round floor ceil truncate abs min max log10 pow`); no files, reflection or assigning. Each `{name}` goes in as a typed value (`Formula.ReadValue`: number, true/false, else text), never pasted text, except inside `"quotes"`. It always takes its slot's kind (`FollowsSlot`), text included. **String Builder**: a text with `{name}`s plus name/value rows that **only that block sees** (block-scoped). **Set Parameters**: run-scoped. Parameters live in `TriggerContext.Parameters` (each run its own copy), always text; nothing is kept between runs. `{name}` looks in the nearest scope first: a String Builder's rows (`TriggerContext.Locals`, via `WithLocals` / `SetLocal`), then the run's parameters, then variables; `{loc.name}`, `{run.name}`, `{var.name}` read only that scope. Persistent values are Data variables/tables.
- **Blocks are getters and setters, the logic is the user's** (If, Expression, Equals around them). Simple options like Toggle next to On/Off are fine.
- **Adding a block:** inherit `ActionBlock` / `ContainerBlock` / `ConditionBlock` / `ValueBlock<T>`, implement `Name`, `Description` (all `[JsonIgnore]`), `ExecuteAsync` / `CheckAsync` / `ComputeAsync`. Logic-capable settings are `ValueSlot<T>`s made in the constructor, listed in `Slots`, `TrackSlots()` at the end of the constructor, saved via `GetData()` / `LoadData()` in a private `[JsonInclude]` property. Fixed settings are `[ConfigurableParameter("Label", ConfiguratorType.X)]` properties whose setter calls `SetParameter(ref _field, value)`; a Menu's options come from `public static List<string> Get{Prop}MenuItems()`, a Slider's range from `Get{Prop}Bounds()`. `BlockResolver` finds blocks by reflection and the block list groups them by component (or `KindGroup`, or a `Group` override). **The class name is the JSON key**: renaming a block class drops saved ones.
- Slots: `BlockSlot` (typed by `ExecutableBlock` / `ConditionBlock`), `BlockSlotList`, `BlockBranchList` (If), value slots. `Filter` narrows what fits, `Lock` refuses blocks for now, `Owner` is the block. Each slot kind has a view model picked in `BlockViewModel` (other components add theirs with `RegisterSlotViewModel`); slots holding slots expose `InnerSlots`. Dropping on a list item inserts before it (`Border.InsertBefore` line, drawn 3px above the item, so a first item's line is outside the list: lists, item presenters and views don't clip (Border.axaml), and scroll areas keep 3px of room at the top inside their visible part). The nearest drop target handles a drag (`DropBehaviorHandler`), unless it passes the payload on (`IDroppable.PassesOn`): then the outer handler passes its own border (`sender as Border`). **Growing lists reorder** (button rows, redeems, Match Text rows, value lists, name/value rows): an item's own binding or block dropped on another item of the same list moves the whole item before it (`GrowingList.Move` via the list's `TryMoveRow` / `TryMoveItem`; the empty one stays last); the boxes inside pass it on to the list, and the list passes on anything else.
- Changes bubble up to `BindableModel.Changed`; saving listens there. Loops call `ContainerBlock.NextPassAsync` each pass (yields to the dispatcher on the UI thread, stops when cancelled).
- **Configs** (`ConfigSet<T>` + `ConfigBar`): the Keyboard, Chat and Events tabs each have named configs and one in use for the whole tab. A tab starts with **none** (nothing can be bound or runs, the page just says "Create a config"); the first is empty, later ones copy the current one, deleting the last returns to none. Keyboard config = every slot's keys by slot id; Chat config = both chat trees; Events config = alerts + redeems. The model's `Root` / `EditableRoot` / `Redeems` / `Events` are the selected config's (null/empty without one).
- Shared bottom editor: `BindableEditorViewModel` (`ShowBindable`, `ShowDraft` for an unsaved draft that binds on its first change, `ClearBindable`); `KeybindViewModel` extends it for keys. Its **Test** button (after the Label box) runs the binding once (`TriggerOnce`) with the Parameters list's values: each listed parameter has a value box (starting from `ParameterInfo.Sample`, else 1 / false / empty by kind), plus growing extra name/value rows; values are remembered by name for the session. This is how every binding is tested (keys, buttons, events, redeems, commands); the Chat tab keeps its own Test above Built-in, which runs a made-up message through both trees.

## Dashboard

- The Chat, Dashboard and Keyboard tabs' lists beside their page share one saved width (`WindowLayoutModel.SideListPanel`). The Dashboard tab (configs, `dashboard.json`) holds **docks** (`DockModel`: fixed id, unique name, kind (no on/off); a console's lines are session-only) laid out as a **split tree** (`DockLayoutNode`: one dock, or a Horizontal/Vertical split with star shares). Only `DashboardConfigModel`'s Try methods change it, and they keep it tidy (a split has 2+ children, never one split the same way) and mend it on load. Dropping a dock or a card on a side of another dock puts it there (`DockView` picks the nearest side). Regions rebuild on `LayoutChanged`; dragging a splitter only saves shares.
- **Dock list** (beside the docks under the config bar, past a splitter, like the Chat tab's block list; the side panel stays empty): a search box, then a card per kind (like the block list), dragged onto a side of a dock (or the empty dashboard) to add one named after its kind. A dock looks like a block (a green `Panel Bound` box, no on/off): its own `PadAll` margin keeps it `ContentGap` from splitters and region edges, name box top-left with its kind's buttons beside it, the hover-only `EditButtons` (drag, remove: `CanToggle` false) top-right, a divider under that row; splitters between docks look like the window's. Bottom panel unused so far.
- Blocks (Dashboard group): **Dock Message** / **Clear Dock** find a console dock by name in the config in use (unknown = error). The app console's block is shown as App Console Message.
- **Button docks:** rows like redeem rows (`DockButtonList`, a `GrowingList`): name box, bind box (edited in the bottom panel via `DockButtonSelection`), ▶ press (`DockModel.TryPressButton`), × delete. Saved in `dashboard.json`.
- **Blocks act on a dock by name** (`DashboardComponentModel.TryFindDock(name, kind)`, in the config in use): an unknown dock, a dock of another kind, or an indicator with no row is an error, never something new made quietly. Only variable docks show something kept elsewhere (the Data tab's variables).
- **Indicators** live on their dock (`DockModel.IndicatorState` / `TrySetIndicator`, by row name, case ignored, session-only, unknown until set). **Set Indicator** (Dock, Indicator; On / Off / Toggle, Toggle turns an unknown one on), **Indicator Is On** (unknown = false). The rows (`DockNameList`, names saved) are name boxes whose text is the status, coloured like a connection's: green on, red off, grey unknown.
- **Variable docks:** rows (`DockNameList`, names saved) of a variable name box + a multi-line value box showing the Data tab's variable of that name, so scripts read/write it with `{var.name}` / Set Variable and no blocks of its own. The value applies on leave (`Commit`; a multi-line box keeps Enter); typing a value for a name with no variable makes a Text variable; a value that doesn't fit is refused and put back. A missing variable's name is grey. Rows refresh from `DataModel` events, only the one whose variable changed (so an edit in another row isn't put back).
- **Timers** (`DockModel.Timers`, a `TimersModel` per timer dock): by name on their dock (several may share one), session-only, kept as end times (paused = time left). `TimerManager` calls `DashboardComponentModel.FinishDueTimers` 10×/s (every timer dock of every config); removing a dock drops its timers without their end. The timer blocks take the dock first. **Start Timer** (If Running: Restart / Add Time / Ignore / Run Another) runs When Done with a copy of the run's parameters from the start and the binding's cancellation; removing the block (`Dispose`, `KillTimersOwnedBy`) drops its timers. **Stop Timer** (Finish Now runs When Done, Cancel doesn't), **Pause Timer**, **Timer Left** (seconds, 0 if none). **Repeat** (Start Timer) makes it go round: running out runs When Done and starts the next lap from the old end (or from now if it fell behind); finishing early or cancelling ends it for good. `AddTime` / `AddTimeAll` (negative takes away): the timer dock's header has a seconds box, its ＋ adds to all, each row's ＋ to that one. A timer dock lists them soonest first with pause / finish now / cancel, and the same three for all of them in its header (`SetAllPaused`, `FinishAll`, `KillAll`); a button dock's header ▶ presses every button (`PressAllButtons`); icons are shapes in `Styles/Resources/Icons.axaml` (`Path.Icon`, the font has no media symbols), coloured from `$parent[Button]` plus a hover rule (a Path isn't inside the template's presenter). No tooltips except the Connections status.

## Keyboard

- `KeyboardInputManager` (raw input, `RIDEV_INPUTSINK` + `RIDEV_DEVNOTIFY`, session lock releases held keys) keeps held keys per keyboard; `KeyDown` fires once per press. `KeyboardDevices` groups raw input connections into physical keyboards by container id; a slot saves its keyboard's main path and finds it again when plugged back in.
- Key codes are Windows VKs, except left/right Shift/Ctrl/Alt use `0xA0`-`0xA5`, numpad Enter is the app's `0x0E`, and numpad keys stay numpad with Num Lock off. Typed `shift`/`ctrl`/`alt` mean either side.
- `KeybindManager` caches nothing (looks the key up on every event) and skips switched-off slots. Keys stay light (edit buttons only on bound keys).
- **Input device boxes:** each slot is a box like a block (green / red when off, a `LineGap` ring, the device dropdown as its header, a divider, the keys `ContentGap` in) with corner buttons: collapse, on/off, drag to reorder, delete (`KeyboardSlotModel.SetIsDisabled` / `SetIsCollapsed`, saved; `KeyboardListModel.TryCreateSlot(layout, index)` / `TryMoveSlot` / `TryDeleteSlot`). Beside them the **input device list** (search + cards, like the dock list): **Keyboard** (a keyboard picture) or **Generic** (every key code, 32×8 grid), dragged in to add one where it's dropped; the layout is fixed by the card.

## Chatbot (Twitch)

- No Twitch library: `TwitchApi` does all HTTP (logins via device code flow, EventSub websocket, Helix). Two accounts: the **streamer** listens (EventSub), the optional **bot** sends chat/moderation (as the streamer if no bot, unless **Chat only as bot**).
- Connections (all integrations): **one attempt** at startup (if connect on startup) or on Connect/Retry; failures are logged once and left Failed, never auto-retried. Logins are refreshed only by the background check (Twitch every 30 min, Spotify every 5), Connect/Retry and startup, never by an action; a refused token marks that account disconnected.
- All Twitch actions share one `TwitchActionQueue` (one per second). Duplicate chat messages get an invisible character so Twitch posts them. Only the app that created a reward can edit it.
- Chat trees: **Built-in** root tried before **Custom** (only a Match Text; `!addcom`/`!editcom`/`!delcom` edit it via `TryAddCommand` etc., walking plain-text rows). Match Text rows are plain text (whole words, case ignored, spacing rules in `ChatText`) or `/regex/` (`//` matches anything). Parse Parameter reads a word or the rest. Has Permission: Anyone < Subscriber < VIP < Moderator < Broadcaster (no Follower: chat doesn't say). A `ChatTarget` is **either** a binding **or** a child block, never both. The first binding reached runs. Bind boxes show the command path.
- **Chat history** (`ChatbotComponentModel.ChatHistory`, `ChatHistoryModel`): the last 100 chat messages' parameters, session-only (Twitch can't read past chat), added by `ChatCommandManager`. The **Chat History** block steps by message id (Newest / This / Older / Newer, staying put at the ends, empty id = newest), so new messages don't move what you're on.
- **App Started** is an Events alert, run once by `AppStartedManager` after the startup connection attempts (max 15 s wait).
- **Events tab:** an **App** section (App Started, `ChatEvents.IsApp`), then **Twitch** (Alerts, then Redeems with New redeem under them), a divider after each source.
- Chat parameters come from `TwitchEvent.ChatParameters`; event/redeem parameter lists are in `ChatEvents` (tests check they match what Twitch and the test panels give: add a parameter in both).

## Other integrations

- **Connections tab:** one `ConnectionRowViewModel` per connection; the connected account's name is only in the status tooltip (the tab can be on stream). A new integration = model (saved connect-on-startup, session-only enabled, reconnect) + manager (`Status`, `StatusChanged`) + a row.
- **Themes tab** (last tab, `Components/Theme`): app-wide for now. **Colors** (`Styles/ThemePalette.cs`: each palette colour and the brushes it paints; a change sets those brushes' `Color` in place, so StaticResource users and code holding a brush follow) above **Spacing** (the base values only). `ThemeComponentModel` keeps only what was changed (typing the default again or Reset drops it), saved to `Config/theme.json`; `ThemeManager` (created first in `MainWindowViewModel`) reads the shipped defaults from the resources, applies the changes at startup and live (a spacing value replaces its resource at the app level, found before `Spacing.axaml`'s).
- **OBS:** obs-websocket v5 directly (`ObsClient`, `ObsManager`), sources by name, empty scene = live scene. Tests use `FakeObsServer`.
- **Spotify:** Web API with PKCE login on `http://127.0.0.1:8974/callback` (plain socket listener). Playback needs Premium. Tests use `FakeSpotifyServer`.
- **Speak Text** (TTS): Windows' installed voices via `System.Speech`, made in memory on a worker thread and played through NAudio (`AudioHelper.PlayWaveAsync`) to any device/volume; free and offline.
- **Voicemeeter:** direct DLL calls; channels by the names its window shows (`VoicemeeterChannels` per edition). The app keeps no Voicemeeter state.

## Data and files

- **Config is JSON** (`Config/*.json`, what you build); **data is SQLite** (`Config/data.db`, what accumulates: variables, quotes, per-viewer rows) via `DataModel` (in memory, Try methods) + `DataStore` (writes each event as a transaction). Built-in tables (columns locked, rows free): `variables` (with its own rules; `{var.name}` reads one), `cooldowns` (label, lastRun: the **Cooldown** block's `DataModel.UseCooldown`, which records the run before letting it through and does nothing while cooling down; a label like `x-{userLogin}` is per viewer). Things the app keeps itself are Text variables (`GetVariableText` / `SetVariableText`, made when first set). Custom tables are free. Table blocks take the table by name (a text slot). **Find Or Add Table Row** (`DataModel.TryFindOrAddRow`: a row by a column's value, made if missing, id in `{rowId}`) + Change Table Value keeps per-viewer totals without an If; **Table Rows** gives rows as text (a `RowQuery`, sorted, the first Count, a row text with the columns as block-scoped `{names}`), e.g. the `!costmore` leaderboard.
- `JsonFileStore`: **a file that can't be read is never overwritten** (the tab shows `BrokenFileViewModel` with Back up & start fresh); small settings files reset with a backup; saves go through a `.tmp` swap with retries (OneDrive). `CredentialStore` writes nothing while auth.json is broken.

## Tests

- `dotnet test StreamAssist.Tests` (not a bare `dotnet test`). `EngineChecks.RunAsync` is one long ordered list of `Check("...", condition)` in `// ---- section ----` blocks, run as one xUnit test. Add/update checks in the matching section when behaviour changes. Test-only blocks (`RecordBlock`, `FixedCondition`, ...) record what ran; helpers `Chatbot()` / `Keyboards()` make models with a config.
- Checks that count console errors must come before the first `await` (AppLog posts through Avalonia's dispatcher).
- Tests never touch the real `Config/` (they use a temp folder) or real OBS/Spotify/Twitch.

## My setup

- Voicemeeter binds on the numpad keyboard set Voicemeeter mutes plus the `OBS Audio` / `Misc Audio` indicators on the `Indicators` dock (I change these myself, check keyboard.json).
- Quotes: `!addquote <message>` (mods) and `!quote` (VIP+) use the custom `quotes` table.
- OBS WebSocket on `localhost:4455` with a password.
- Goose Party: shows OBS source Goose Party (scene Common) and starts a 10 s timer on the `Timer` dock whose When Done hides it.

## Known issues (not fixed yet)

- `KeyboardSaveManager.Dispose` cancels the pending save instead of saving, so changes in the last second before closing are lost.
- `KeyboardSlotModel.Dispose` disposes the selected device, which it doesn't own.
- A repeated block error (e.g. a broken chat command) is logged every time it runs, not once.
