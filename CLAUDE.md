# StreamAssist — context for Claude

An "everything app" for streamers (Windows, .NET 10, Avalonia 12, CommunityToolkit.Mvvm): input binds (keyboards, mice, controllers, mic talking), a Twitch chatbot, alerts / redeems, a dashboard, Voicemeeter, OBS, Spotify, TTS and SQLite tables, all driven by Scratch-like blocks. It glues existing tools together. This file is rules and non-obvious parts; details live in the code and its comments.

- Don't fix unrelated bugs unless asked, point them out. No changes for the sake of changes. Commit only when asked.
- Never read or print `Config/auth.json` or any secret/token.

Back up a config file before editing it, and read it first (I may have changed it).

- Don't simulate clicks or typing in the app (they can land in another window).
- **Input must keep working while the app isn't focused:** raw input is registered with `RIDEV_INPUTSINK` on the main window. Never route input through anything that needs focus.

Short (5-10 words), no full stop, details in brackets at the end: `can't send chat message, twitch not connected`. A block's error starts with its name and is logged every time it happens (spam means fix or disable it, never silence it). Asking for what's already the case is silent success, except something I named that isn't there. Ask before adding any other kind of message.
- Twitch blocks act only on my own channel. The bot account only has chat + moderation scopes; everything else is done as the streamer. Built-in chat commands confirm briefly in chat (`Command !lurk added`).
- Small buttons always go top right, unless I say otherwise.

## Architecture

- `Shell/`: main window, panels, `GlobalContext` (static service locator), `MainWindowViewModel` (composition root: loads models, creates managers, a fresh tab file starts with a config named Default), `WindowLayoutModel` (`window.json`: window, tab, panel sizes by name).
- `Components/<Name>/`: **Model/** (data only, JSON, raises events, never does work), **Background/** (managers made once at startup: listen to models, do the work), **UI/** (view models made when a tab opens, disposed when it closes; they change things only through model methods). Flow: UI → model method → model event → background + UI. Blocks live in the component's `Actions/`, `Conditions/`, `Values/`, `Containers/`; `Components/Blocks/` is the block system and the generic blocks.
- `Core/` knows nothing about features: `Persistence/` (`JsonFileStore`, `CredentialStore` (every secret in git-ignored `Config/auth.json`), `AppPaths`, `DelayedSave`), `Utilities/` (`GrowingList<T>` always ends in one empty item, `Formula`), `Mvvm/` (bases, `CommitOnLeave`, `Flash`), `Controls/` (`PriorityStackPanel`: drops its lowest-`Priority` children when short of room), `Dragging/`.
- `AppPaths`: the app folder is the exe's, or the project folder when run from `bin/`. `Config/` and `Assets/` (Sounds, Images, Videos, Voices) are git-ignored; block paths are relative to `Assets/` and can't leave it.
- **Everything the UI can do is a public model method** with the rules in the model. Public `TryXxx` validates, logs `AppLog.WriteError`, returns bool, calls a private `Xxx` that does the work and raises the event.
- Subscriptions via paired `SubscribeToXxx` / `UnsubscribeFromXxx`; `Dispose()` unsubscribes everything; keep a reference to what you subscribed to.
- JSON: public getters `[JsonIgnore]`, saved through private `[JsonInclude] [JsonPropertyName("camelCase")]` properties; cross-links resolve in `OnDeserialized` / `AttachXxx`. Saving: managers listen to model events (`DelayedSave` for bursts, written on close).
- Style: `_camelCase` fields set in the constructor, `// section` headers, three blank lines between members, comments say why. `CallbackBlocker` stops UI → model → UI loops.
- Threading: everything on the UI thread. Other threads (integrations, audio capture, clipboard) `Dispatcher.UIThread.Post` before touching models.

## XAML / look

- `ViewLocator` maps `FooViewModel` → `FooView` (same namespace). View-only styles in the view's `<UserControl.Styles>`. Class names are case-sensitive.
- **Nothing typed in views:** colours from `Brushes.axaml` (palette named by meaning), sizes from `Sizes.axaml` / `Typography.axaml`, spacing base values from `Spacing.axaml`; any other margin/padding/border/rounding is a recipe in `Styles/Gap.cs` (`Margin="{s:Gap PadAll}"`, letters = base values, `P` = ContentGap − LineGap). Anything the Themes tab changes must be `DynamicResource` or `{s:Gap}`. A new margin gets a recipe (reuse one of the same shape); a new base value goes in its resource file and `SpacingRecipes`. Only font trims and the insert line's maths stay typed.
- **What I made is outlined green** (`Bound`; red when off); permanent things are divider lines and plain text. Outlines only, no fills (panel fill is black at alpha 1, not Transparent, so it's hit-testable). **Everything clickable has a border.** Ghost fields (`Ghost` brush): "new thing" boxes (`TextBox.New`) and empty slots (`DropZone`).
- Buttons `Small` (corner, `SmallButtonSize`) / `Medium` (control height), `Square` for icons, full-width `＋` / `－`. Icons are shapes in `Icons.axaml`. Corner `EditButtons`: copy, collapse, on/off (－ while on, ＋ while off), drag, remove; only the innermost thing under the pointer shows them.
- **No hover tooltips** (the Connections tab's status boxes are the only ones): say it in the label or placeholder instead.
- A box whose value the view model may reset (cleared "new" boxes, refused values) commits on leave (`CommitOnLeave`, `Commit` class), not by binding Text directly. Enter applies it, except in multi-line boxes.
- **Spacing (keep exact, measure pixels after changing):** line widths `ThinLineThickness` / `ThickLineThickness`. Every line keeps `LineGap` clear on each side through its own style (dividers, splitters, window edge, Gapped scrollbars); nothing else goes in that zone. Content is `ContentGap` from every line (regions pad `ContentPadding` inside the zones). Content to content: `Small` / `Medium` / `Large` × `Horizontal` / `VerticalGap`, set on the container (`Spacing`), not as margins. Big titles: `LargeVerticalGap` above and below every one, from its container's spacing; `TextBlock.Title` trims the font's own space, `Title UnderLine` for the first one under a line (a line gives only ContentGap). No margins on titles in views, and no one-off spacing fixes: a new case gets a style rule. Subheadings `MediumVerticalGap`, everything else Small.
- Boxes (blocks, docks, input boxes): their border is a line, so a `LineGap` ring inside it; nested blocks sit at the ring at the sides, content pads `ContentPadding` more. Block: title, `MediumVerticalGap`, rows `SmallVerticalGap` apart, body ends `ContentPadding` above the ring. A label is `SmallHorizontalGap` from its box measured from the colon (`TextBlock.Colon`). Single-line controls are `ControlHeight`; bordered boxes grow with their text between `ControlMinWidth` / `ControlMaxWidth`, each on its own; boxes in a stretching column are left-aligned.
- Panel ScrollViewers: `Classes="Gapped"` (pages of sections + dividers: `Gapped Lined`), content `ScrollInset`, main areas end with `ScrollEndPadding`. Insert lines draw 3px above an item, so lists and presenters don't clip.

## Blocks

- Every trigger (key, chat row, redeem, alert, dock button) owns a `BindableModel` whose root is a `BlockSlotList`. `TriggerStart/Stop/Once` run the root blocks in turn with a `TriggerContext` (phase, cancellation, parameters); async, pass the token to waits; disposing a bindable cancels its runs. Loops call `NextPassAsync`.
- Errors: `throw Fail("reason")` logs `<block>: <reason>` and stops the run; **Stop** ends it quietly. A disabled block skips itself and its contents.
- Kinds: `ContainerBlock`, `ActionBlock`, `ValueBlock<T>`, `ConditionBlock` (bool; disabled/empty = false), `AdaptableValueBlock` (takes its slot's kind).
- **Values:** a logic-capable setting is a `ValueSlot<T>`: typed text (`{name}` filled in, then read as the slot's kind) or a value block in it (wins). `ValueTypes` decides conversions. Scopes: `{name}` looks at a String Builder's rows, then the run's parameters (Set Parameters), then variables; `{loc.}` / `{run.}` / `{var.}` pick one. Parameters are text, per run. **Expression** (`Formula`, DynamicExpresso): typed C#, `{name}` goes in as a typed value, no files/reflection/assigning.
- **Blocks are getters and setters, the logic is mine** (If, Expression, Equals around them).
- **Adding a block:** inherit a kind, implement `Name`, `Description` (`[JsonIgnore]`) and Execute/Check/Compute. Logic-capable settings are `ValueSlot<T>`s made in the constructor, listed in `Slots`, `TrackSlots()` at the end, saved via `GetData` / `LoadData` in a private `[JsonInclude]` property. Dropdowns are `MenuSlot`s (they take value blocks and pastes); only a dropdown that shapes the block (its output kind, Reads) or is read during synchronous chat matching stays a fixed `[ConfigurableParameter]` menu. Other fixed settings are `[ConfigurableParameter]` properties. `BlockResolver` finds blocks by reflection, grouped by component; big groups split into `Subgroup`s (a heading inside the group's). **The class name is the JSON key**: renaming a block class drops saved ones.
- Slots and drops: each slot kind has a view model (`BlockViewModel`, `RegisterSlotViewModel`). The nearest drop target takes a drag (`DropBehaviorHandler`) unless it `PassesOn`. Growing lists reorder by dropping an item on another (`GrowingList.Move`).
- **Copy / paste** (`BlockClipboard`, system clipboard JSON `{"streamAssist": kind, "data"}`, re-read on window focus): a paste is a drop of a fresh copy, so the target's own `CanAcceptDropPayload` decides. Kinds: `block`, `binding` (whole binding, keys/bind boxes only), `inputDevice`, `dock` (onto Blank docks). `PasteButton` shows on hover where a paste would be taken. Components add kinds with `RegisterKind`.
- **Configs** (`ConfigSet<T>` + config bar) on Input, Chat, Events, Dashboard, Themes: one in use per tab; none = nothing runs, "Create a config"; a new one copies the current one.
- Bottom editor `BindableEditorViewModel` (`KeybindViewModel` for keys): **Test** runs the binding once with the Parameters list's values.

## Features (non-obvious parts)

- **Dashboard** (`dashboard.json`): docks in a split tree (`DockLayoutNode`), changed only through `DashboardConfigModel`'s Try methods, which keep it tidy. Blocks find a dock by name (`TryFindDock(name, kind)`): unknown / wrong kind / missing row is an error, never made quietly. A turned-off dock takes no changes, quietly (running timers still end; reads still work). Indicators, timers and sounds are session-only and live on their dock; variable docks show Data variables. Timers and sounds with no Dock run in the background where nothing can control them; sending them to a dock is how you get control.
- **Input** (`input.json`): `DeviceInputManager` (raw input keyboards + mice, XInput controllers polled, Windows audio inputs as microphones) raises `KeyDown/KeyUp(devicePath, code)`; `KeybindManager` looks the code up each time. Everything is a key code: keyboard VKs (left/right Shift/Ctrl/Alt `0xA0`-`0xA5`, numpad Enter `0x0E`), mouse `0x01`-`0x06` and wheel `0x3A`-`0x3D` (wheel input doesn't arrive yet, unresolved), gamepad `0xC3`-`0xDA`, mic Talking `0xFF`. Devices group by container id **and kind**. A box's layout fixes its picture (`DevicePictures`) and device kind (Generic takes any but mics). `MicrophoneManager` captures picked inputs and decides talking (threshold, hold) every 20 ms. Key names: `KeyNames`.
- **Chatbot:** no Twitch library (`TwitchApi`: device code login, EventSub, Helix). Streamer listens, optional bot sends. Connections (all integrations) try **once** at startup or on Connect/Retry, failures logged once, never auto-retried; logins refresh only in the background check. Twitch actions share one queue (1/s). Built-in chat tree tried before Custom (`!addcom` etc. edit Custom). A `ChatTarget` is a binding **or** a child block. Chat history: last 100 messages, session-only. Event/redeem parameters are in `ChatEvents` (tests check them against Twitch and the test panels: add a parameter in both).
- **Widgets** (`widgets.json`): things drawn on stream, each its own OBS browser source served by the app (`http://127.0.0.1:<port>/widget/<name>`, plain sockets, port on the Connections tab, pick once). Like docks: blocks find them by name in the config in use; settings are the box's, OBS is where they're placed. The app times spins and plays their sounds (its own audio, not OBS's); pages only draw what they're sent.
- **Themes** (`theme.json`): named themes, each keeps only what it changes. Colours set brushes' `Color` in place (`ThemePalette`); numbers replace resources at app level (`ThemeManager`, created first).
- **OBS** (obs-websocket v5, `ObsClient`), **Spotify** (PKCE on `127.0.0.1:8974/callback`, playback needs Premium), **Voicemeeter** (DLL, channels by their window names, no state kept). Tests use `FakeObsServer` / `FakeSpotifyServer`.
- **Speak Text:** Windows voices or Kokoro (`KokoroVoices`, sherpa-onnx, model in `Assets/Voices/kokoro-multi-lang-v1_0`, Apache 2.0); made off the UI thread.
- **Data:** config is JSON, data is SQLite (`data.db`: variables, cooldowns, custom tables) via `DataModel` + `DataStore`. `JsonFileStore` never overwrites a file it can't read (the tab offers Back up & start fresh); saves swap through `.tmp` with retries (OneDrive).

## Tests

- `dotnet test StreamAssist.Tests` (not bare `dotnet test`). `EngineChecks.RunAsync` calls the section methods in order; each section (`// ---- name ----`, `Check("...", condition)`) lives in `EngineChecks.<Area>.cs`; add checks in the matching section. Tests use a temp folder, never `Config/` or real services.
- Sections that count console errors (`Dispatcher.UIThread.RunJobs()`) run before the first awaited section: after an await they're on another thread and fail ("the calling thread cannot access this object").
